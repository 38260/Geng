# 赶梗潮｜前端 UI 复刻开发提示词

你现在负责实现「赶梗潮」前端页面。

## 一、最高优先级：严格参考项目目录中的设计图

**在开始编写任何前端代码之前，必须先检查项目目录中的所有图片资源。**

重点搜索：

```
./
./assets/
./public/
./src/assets/
./docs/
./design/
./images/
./mockup/
./screenshots/
```

以及其他可能存放设计稿、UI参考图、产品截图的目录。

### 设计图优先级规则

如果项目目录中存在我提供的「赶梗潮」UI设计图：

> **必须优先以项目目录中的设计图作为唯一主要视觉参考，并尽可能 1:1 复刻。**

不要重新设计一套自己的 UI。

不要因为“更符合常见 SaaS 设计”而擅自修改布局。

不要自行替换颜色、字体、间距、卡片结构、导航方式或信息层级。

设计图中的：

- 页面结构
- 布局比例
- 栅格
- 侧边栏
- 顶部导航
- 卡片位置
- 卡片尺寸
- 圆角
- 阴影
- 字体层级
- 字号
- 字重
- 颜色
- 图标位置
- 图表位置
- 按钮位置
- 标签样式
- 空白区域
- 图片比例
- 信息密度
- 页面间距

都应该尽可能按照参考图还原。

## 二、参考图不是“灵感”，而是 UI Specification

把参考图理解成：

> **视觉设计 Specification / UI 设计稿**

而不是：

> “参考一下这种风格，然后自己设计。”

如果参考图与常规前端设计习惯发生冲突：

**优先遵循参考图。**

如果某个区域在参考图中明显留白：

**不要为了增加信息而填满。**

如果参考图中的文字很少：

**不要自行增加大量说明文字。**

如果参考图中的卡片很简洁：

**不要添加额外指标。**

# 三、整体视觉目标

产品：

**赶梗潮**

核心定位：

> B站网络梗热度与生命周期分析平台

核心问题：

> 今天该玩什么梗？
>
> 这个梗现在有多火？
>
> 现在赶还来得及吗？

视觉方向：

> **B站 × Linear × 潮流榜单**

整体应该：

- 年轻
- 清爽
- 有一点互联网梗文化
- 有数据产品感
- 轻量
- 有趣
- 不严肃
- 不像企业 BI
- 不像 ChatGPT
- 不像传统后台管理系统

# 四、严格禁止的视觉风格

禁止：

- 紫色 AI 渐变
- 蓝紫色科技光效
- AI 大脑
- AI 芯片
- 神经网络
- 机器人 AI 图标
- Cyberpunk
- 3D 科技球
- 大面积玻璃拟态
- 巨型渐变 Hero
- 企业 SaaS Dashboard 风格
- 密集 BI 大屏
- ChatGPT 聊天框
- AI 助手形象
- 复杂 Agent 工作流视觉

**AI 是系统能力，不是产品视觉主题。**

# 五、信息密度要求

这是非常重要的要求。

参考图已经确定了产品的信息密度。

实现时：

> **宁可少显示信息，也不要把页面塞满。**

每个页面只展示最重要的信息。

例如首页：

```
今天，赶什么梗？

今日热榜
↓
5 个热门梗

精选推荐
↓
3～4 个梗
```

不要在首页同时展示：

- 大量统计指标
- 复杂趋势图
- 详细数据表
- 长篇 AI 分析
- 大量说明文字

# 六、页面结构

V1 主要实现三个页面。

## Page 1：首页

页面标题：

```
今天，赶什么梗？
```

副标题：

```
B站网络梗热度与生命周期分析平台
```

顶部：

```
赶梗潮 Logo
搜索框
日期
用户头像
```

左侧导航：

```
首页
梗库
热度趋势
我的收藏
```

首页主要区域：

### 筛选

```
全部
正在爆
快起飞
退潮中
```

### 今日热榜

展示 5 个梗。

每个卡片只展示：

```
排名
图片
梗名称
热度
生命周期
最近7天讨论量变化
查看详情
```

例如：

```
🥇

电子木鱼

🔥 92

正在爆

最近7天讨论量 +142%

查看详情 →
```

不要增加大量字段。

## Page 2：梗详情

示例：

```
电子木鱼
```

顶部展示：

```
梗图片

电子木鱼

🔥 92

正在爆

🟢 还来得及
```

核心指标：

```
相关视频
1.2K
+68%

参与UP主
326
+42%

评论
18.2K
+51%

弹幕
52.7K
+74%
```

### 热度趋势

使用 ECharts。

展示：

```
7天
30天
```

折线图。

不要做成复杂 BI 图表。

保持参考图中的简洁风格。

### 生命周期

展示：

```
🌱 萌芽期
📈 上升期
🔥 爆发期
🌊 平稳期
📉 退潮期
🪦 过气
```

突出当前阶段。

例如：

```
📈 上升期
```

### 赶梗判断

这是页面最重要的判断。

例如：

```
现在赶这个梗？

🟢 还来得及

热度仍在上涨，
参与创作的人也越来越多。
```

或者：

```
🟡 慎赶
```

或者：

```
🔴 你来晚了
```

### 趋势解释

只显示非常短的自然语言。

例如：

```
最近一周相关内容增长明显，
参与创作的UP主数量也在增加。
```

不要出现：

```
AI认为……
根据大模型分析……
经过AI智能判断……
```

### 相关视频

展示 3～4 个 B站视频卡片。

每个卡片：

```
缩略图
标题
UP主
播放 / 评论等核心数据
```

不要展示大量文字。

# 八、颜色

如果参考图已经存在：

> **优先从参考图中提取颜色。**

不要自行创造新的颜色体系。

如果参考图无法读取颜色，再使用：

```
背景：#F7F7F5
主文字：#181818
主强调色：#FF6B5F
```

辅助颜色：

```
绿色：上涨 / 还来得及
蓝色：趋势 / 平稳
红色：爆发 / 高热度
灰色：退潮 / 过气
```

颜色应该克制。

# 九、字体与文字

中文 UI 优先使用现代无衬线字体。

标题可以有一点手写/潮流感，但正文必须清晰。

严格控制文字数量。

例如：

错误：

```
这个梗目前正在经历快速增长阶段，
根据过去七天的相关数据可以观察到……
```

正确：

```
最近7天讨论量明显上涨。
```

# 十、图片

如果项目目录中已经存在：

- 梗图片
- Logo
- Mascot
- UI截图
- 插画
- 图标
- 视频缩略图

**优先直接使用这些资源。**

不要生成风格完全不同的新图片。

如果缺少图片，可以使用 Mock 图片，但必须保持：

> **尺寸、比例、圆角、裁剪方式与参考图一致。**

# 十一、响应式

桌面端优先。

设计参考图以 Desktop 为主要目标。

同时保证：

```
Desktop
Tablet
Mobile
```

基本可用。

但：

> 不要为了响应式破坏 Desktop 参考图的 1:1 布局。

# 十二、组件实现原则

不要把整个页面写成一个巨大组件。

合理拆分：

```
components/
├── Sidebar
├── Header
├── MemeCard
├── RankingList
├── TrendChart
├── Lifecycle
├── CatchUpStatus
├── MetricCard
├── VideoCard
└── RecommendationCard
```

页面：

```
pages/
├── Home
├── MemeDetail
└── Settings
```

# 十三、数据与 UI 解耦

不要把 Mock 数据直接硬编码在 JSX 中。

建议：

```
src/
├── api/
├── types/
├── data/
├── components/
├── pages/
└── utils/
```

Mock 数据独立。

例如：

```
data/mockMemes.ts
data/mockVideos.ts
```

这样后续接真实 API 时不需要重写 UI。

# 十四、重要：参考图检查流程

开发前：

```
1. 扫描项目目录
2. 找到所有 png / jpg / jpeg / webp / svg
3. 找到疑似 UI 设计图
4. 阅读并理解参考图
5. 确认页面数量
6. 确认布局结构
7. 确认颜色
8. 确认字体层级
9. 确认信息密度
10. 再开始编码
```

开发过程中：

```
实现页面
↓
运行项目
↓
截图
↓
与参考图进行视觉对比
↓
调整
↓
再次截图
↓
继续调整
```

# 十五、必须进行视觉验收

完成后不要只检查：

```
代码有没有报错
```

还必须检查：

```
是否像参考图
```

重点检查：

### 1. 布局

```
侧边栏宽度
顶部高度
内容区域宽度
卡片位置
卡片间距
```

### 2. 信息密度

```
有没有文字太多？
有没有卡片太多？
有没有额外增加指标？
```

### 3. 视觉

```
颜色是否一致？
圆角是否一致？
阴影是否一致？
字体层级是否一致？
```

### 4. 图片

```
图片比例是否一致？
图片裁剪是否一致？
```

### 5. 图表

```
是否简洁？
是否与参考图布局一致？
```

# 十六、1:1 复刻原则

如果参考图足够清晰：

> **目标不是“做一个类似的页面”，而是“尽可能复刻这张图”。**

允许：

- 根据实际数据调整数字
- 根据实际组件进行合理技术实现
- 根据浏览器尺寸做微小响应式调整

不允许：

- 自行重新设计
- 自行增加模块
- 自行改变页面结构
- 自行增加大量文字
- 自行改变视觉风格
- 自行加入 AI 科技感
- 自行把页面改造成传统 Dashboard

# 十七、功能优先级

如果时间有限：

```
第一优先级
视觉还原

第二优先级
页面结构

第三优先级
交互

第四优先级
真实数据

第五优先级
高级动画
```

不要为了增加功能而牺牲 UI 还原度。

# 十八、最终目标

最终打开网站时，用户应该第一眼感觉：

> “这就是参考图里的那个产品。”

而不是：

> “这是一个参考了这张图重新设计的网站。”

**视觉一致性优先于功能堆叠。**

**简洁优先于信息量。**

**参考图优先于 Agent 自己的设计判断。**
