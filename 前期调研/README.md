## 一句话结论

B 站的梗有明确的生命周期，但用户只能看到爆火后的结果，判断不了"正在崛起"还是"已经过热"。
赶梗潮拿 B 站梗相关视频的传播数据算一把可跨梗比较的尺子，输出三件事：
**这个梗现在多少分、走到哪一段、现在赶还来不来得及。**

起点是一个具体的例子：2026 年 9 月 21 日，「梗百科」发了《闪身步是啥梗？》，播放 64.6 万；
五天后（9 月 26 日），闪身步在自算的热度指数上排当日第一。从"有人把它讲明白"到"它火到不能再拖"，
中间只有 5 天。这个项目研究的就是这 5 天。

## 现状速览（详见 02）

- **学术界**把梗当文本和文化现象研究得多，给出可复算时间度量的少；计算机一侧量化的是新闻、话题标签、
  单条视频，不是"梗"这个跨视频、跨创作者的聚合对象。两头中间是空的。
- **同类产品**里，百度/微信指数度量的是搜索词，「松弛感」这类口语词会混进大量无关检索；
  微博热搜、各平台热榜是存量快照，梗崩了当天照样挂榜；新榜、飞瓜、蝉妈妈做的是创作者与电商侧的数据，
  不回答"这个梗还能火多久"。
- **合规**是这个项目必须正面写清楚的一块。B 站《用户使用协议》5.6(3) 明确禁止用爬虫等自动程序获取平台数据；
  2026 年 1 月和 7 月，两个最主流的 B 站 API 开源仓库先后收到律师函并关停；
  2026 年 4 月北京互联网法院首次适用《反不正当竞争法》新增的数据专款判案。
  本项目的应对是：只取公开元数据、不登录、不绕技术措施、限频、研究用途非商业，并把数据来源标在页面上。

## 量化方案速览（详见 03）

热度指数 0–100，五个分量：

```
热度 = 0.25×播放 + 0.20×互动 + 0.16×内容规模 + 0.14×参与UP主 + 0.25×增长
```

三条设计决定：绝对量先做**对数区间归一化**（否则一条爆款吃掉整榜）；增长权重给到 0.25 且只看
**最近 7 天 vs 前 7 天**；样本不足时**不外推**，显示"—"而不是 +585% 这种噪声。
生命周期分六段（萌芽→上升→爆发→平稳→退潮→过气），另有一个不是阶段的状态叫「数据不足」——
最近 7 天真正观测到的天数少于 4 天，算法拒绝给结论。

## 数据 Demo 速览（详见 04）

`04_数据源与处理Demo/` 里有一个能独立跑的小脚本，2026-10-05 用 B 站真实接口抓了 4 份原始返回体
（2 个梗 × 4 个自然日，共 120 条视频记录），走完 采集 → 清洗 → 聚合 三步：

```
原始 120 条  →  相关性过滤掉 35 条  →  入库 85 条（保留率 70.8%）
```

被过滤掉的都是真实噪声：标题里没有梗名、只是标签里蹭了一个"琵琶曲"的视频。
这就是"搜索返回 ≠ 相关"的具体样子。
