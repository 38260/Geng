# 赶梗潮 · 微信小程序

`miniprogram/` 是独立于 `frontend/`（Web）的第二端：**Taro 4 + React + TypeScript**，
一份源码出两个目标。

| 目标 | 命令 | 产物 | 用途 |
| --- | --- | --- | --- |
| 微信小程序 | `npm run build:weapp` | `dist/weapp/` | 交给微信开发者工具上传 |
| H5 预览 | `npm run build:h5` | `dist/h5/` | 手机浏览器看效果，也用来做视觉核验 |

只做**只读**：小程序不调 `/api/manage`、`/api/jobs` 这些写接口——V1 没有登录体系，
那些接口本来就没鉴权，把它们接到小程序等于把改数据的口子开到公网。

## 一、跑起来

```bash
cd miniprogram
npm install                 # 依赖装的是 Taro 4.1.6 + React 18
npm run build:weapp         # 产出 dist/weapp
```

然后打开**微信开发者工具**：导入项目 → 目录选 `miniprogram/`（不是 `dist/`，
`project.config.json` 里 `miniprogramRoot` 已指向 `dist/weapp/`）→ AppID 填自己的，
没有就选"测试号"。

后端默认打 `http://127.0.0.1:8010`。开发者工具右上角 **详情 → 本地设置 →
勾选「不校验合法域名…」**，模拟器才能连本机 HTTP。

真机预览时手机连不到你电脑的 `127.0.0.1`：在小程序「口径」页把后端地址改成
电脑的局域网 IP（如 `http://192.168.1.20:8010`）保存即可，存在 storage 里、
不用重新编译。

## 二、上线前必须做的三件事

1. **HTTPS + 合法域名**：微信只允许 `https` 且在小程序后台配过的域名。
   本机 HTTP 只能用于开发。
2. **给 `/api/manage/*` 加访问控制**：这些写接口现在无鉴权（见根 README 的
   「安全」一节），公网部署前必须先加。
3. **AppID**：`project.config.json` 里是占位的 `touristappid`，换成自己的再上传。

## 三、页面

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| 热榜 | `pages/home` | 过了"活着"门槛的梗，卡片带热度/阶段/赶梗/认证标签，下拉刷新、触底分页 |
| 梗库 | `pages/library` | 完整梗库（含没上热榜的），搜索（名称/别名/关键词）+ 四种排序 |
| 详情 | `pages/detail` | **梗介绍**、热度四指标、趋势柱、生命周期、赶梗判断、相关视频（真实封面 + **B站默认排序 / 播放量两档可切**）、这条数据的口径 |
| 口径 | `pages/about` | 热榜/梗库/被挡/候选池四个数、准入与门槛规则原文、热度算法、后端地址切换 |

详情页的介绍块与 Web 端同源（`backend/app/services/meme/intro.py`），四档来源依次是
人工撰写 > **字幕原文摘录**（AI 只能整句照抄着缩短）> 解说视频标题与简介**原文**拼出的证据 >
明说「暂无介绍」不留白。字幕块在小程序里是折叠的：默认只给挑出来的那几句，
点「展开字幕原文」才看整段，旁边标清楚是人工 CC 还是 AI 识别字幕、这条视频是不是双 UP 认证的。
相关视频与出处都带真实封面，点一条的行为按平台分叉：
H5/浏览器直接打开那条视频；**微信小程序开不了站外链接**（`<web-view>` 要把 bilibili.com
配成业务域名并上传校验文件，域名不归我们所有），所以退成复制到剪贴板 + toast 说明，
行尾标签也跟着写成「打开」或「复制」，不让人以为点了没反应。

## 三点五、与 Web 端的功能对照

Web 有 7 个页面，小程序 4 个 tab + 1 详情页。差的部分**一半是刻意的**：

| Web | 小程序 | 说明 |
| --- | --- | --- |
| 首页（Hero + 今日热榜 + 精选推荐 + 筛选） | 首页（同结构，精选推荐横向滑） | 精选推荐规则与 Web 的 `pickFeatured` 一致，有单测锁住 |
| 梗库（搜索 + 排序 + 全库） | 梗库（同 + 收藏筛选） | 行内补了热度条、7 天增幅、赶梗标签 |
| 热度趋势（全梗排行表） | 梗库行即总览 | 手机上表格放不下，改成"名字 + 热度条 + 增幅 + 结论"一行 |
| 梗详情（介绍/趋势/生命周期/赶梗/视频/UP/认证） | 详情（同 + 视频可展开全部 + 交叉跳转） | 详情页「看它在所有梗里的位置」跳梗库并带搜索词 |
| 我的收藏（独立页） | 梗库「我的收藏 N」筛选态 + 口径页列表 | 不做第 4 个 tab；筛选态里额外显示收藏时间 |
| 梗管理（写封面/介绍/别名） | **不做** | `/api/manage/*` 无鉴权，接到小程序等于把改数据的口子开到公网 |
| 系统设置（LLM 配置） | **不做** | 同上，且 Key 不该进任何客户端 |
| 数据刷新面板（手动/定时） | **不做**（只读显示上次刷新时间与自动配置） | 刷新会打 B 站、写库，是运维动作 |
| 趋势解释 / 重新判断（AI 文案） | **不做** | 那是 `POST /api/memes/{id}/insight`；小程序展示算法自己写的那句理由，不额外引 LLM 依赖 |

## 三点六、返回入口

微信给详情页的原生返回箭头只在**页面栈不止一页**时出现，所以有两种情况用户会没有返回入口，
这两种情况下页面左上角会自动多出一枚轻量的返回条（`components/PageBack.tsx`）：

| 情况 | 显示 | 点了去哪 |
| --- | --- | --- |
| 从热榜点进详情（正常路径，weapp） | 不显示——原生箭头本来就在左上角 | — |
| 从分享卡片/扫码直接落到详情（页面栈只有 1 页） | 「‹ 回热榜」 | `switchTab` 回首页 |
| H5 预览（手机浏览器打开 `dist/h5`） | 「‹ 返回」或「‹ 回热榜」 | 有栈就 `navigateBack`，没栈回首页 |

H5 预览要单独处理是因为 **Taro 编出来的 H5 不画微信那个导航栏**（只改 `document.title`），
所以浏览器里任何页面都没有返回入口——这不是小程序上线后的样子。

## 四、分享

四个页面都接了 `useShareAppMessage`，转发路径带上下文：

| 页面 | 分享标题 | 落点 |
| --- | --- | --- |
| 详情 | 「闪身步」现在赶还来得及吗？ | `/pages/detail/index?id=51` |
| 热榜 | 今天赶什么梗？B 站热榜 12 个活梗 | `/pages/home/index` |
| 梗库 | B 站梗库 31 个梗，热度与生命周期都能查 | `/pages/library/index` |
| 口径 | 赶梗潮：这些数字是怎么算出来的 | `/pages/about/index` |

标题刻意写成一句人话问句，不出现"AI 智能分析"这类词。详情页右上角还有一个
「分享」按钮（`open-type="share"`）——小程序里没有"复制链接"这种原生入口，
转发才是它的分发路径。

两点没做，原因写在代码注释里：**不用自定义分享图**（B 站封面有防盗链，
跨端引用不稳，宁可让微信截默认页面图）；**不开朋友圈单页模式**（`shareTimeline`
打开的是受限的 singlePage 环境，本机没有开发者工具无法核验，宁可不给）。
`open-type="share"` 只在微信里生效，H5 预览上那个按钮点了没反应，属正常。

## 五、收藏（本机）

V1 不做账号体系，所以收藏**只写在这台设备的本地存储里**：不上传、不跨端同步，
和 Web 端 localStorage 里那份互不可见，换手机或清缓存就没了——这句话在详情页
按钮的 toast、梗库的收藏说明、口径页的收藏卡片上都写了一遍。

存的是 `{id, name, at}`，**不存梗的数据副本**：热度每天都在变，收藏页要的是实时数，
所以列表靠 `GET /api/memes?ids=51,42` 现取（这个参数是为收藏功能加的，
上限 100 个 id，脏输入忽略、超限截断）。入口有三处：详情页「收藏」按钮、
梗库顶部「我的收藏 N」pill、口径页的列表与「清空本机收藏」。

## 六、响应式做法

- 样式里写小写 `px`，Taro 按 `designWidth: 750` 编译成 `rpx`，跟着屏宽缩放；
  不想跟着放大的（1 物理像素分割线、平板上给内容列封顶）写大写 `PX`。
- 底部留 `calc(env(safe-area-inset-bottom) + 140px)`，最后一张卡不会被 Home 条压住。
- `@media (min-width: 500PX)` 把内容列封顶 480PX 居中，iPad/桌面大屏不会拉成横幅。
- 数字统一 `font-variant-numeric: tabular-nums`，榜单右对齐不抖。

## 六点五、图从哪来

Web 端 Hero 右侧那截水彩（「现在不赶就晚了！」+ 戴耳机的吉祥物）是从参考 UI 直接裁下来的
**不透明**位图，在桌面端靠"卡片底色和素材底色同色"糊过去。手机上它要贴在卡片右下角一小块，
糊不住，必须真透明 —— 于是有了：

```bash
python scripts/cut_mp_assets.py     # 输出 src/assets/hero/，改坐标后重跑即可
```

| 文件 | 用在哪 | 怎么来的 |
| --- | --- | --- |
| `hero-art.png` | 首页 Hero 右下角 | 标语 + 吉祥物一整块。两者在参考图里是咬合的（标语那根"!"压在吉祥物头上），拆开切会各自带进对方的碎片 |
| `mascot.png` | 空态 / 错误态 | 只留吉祥物，"!"用矩形点名抹掉；帽子顶不能被切，所以从 y=170 起切 |
| `underline.png` | 标题下那道珊瑚红横扫 | 从参考图标题下方那条笔刷按"有多珊瑚红"给 alpha，黑毛笔字和蓝色副标题会自动掉 |

抠图做法与两个坑：

- **不用阈值法抠背景**。吉祥物身体是白的，阈值法会连身体一起吃掉；改成从四边向内做容差
  漫水填充，只抠"与边框连通"的近背景色，被描边包住的白色身体和水彩笔触都保留。
- **底边要渐隐**。素材是被参考图那条带子的底边拦腰切断的，直接摆在卡片上会露出一道硬边，
  所以最后 16% 高度把 alpha 线性压到 0。
- **H5 的 `<Image>` 会自己跑偏**。Taro 把它编译成一个 `position: absolute` 的 `<img>`，
  它没有 `left/top`，于是按静态位置摆——而静态位置受卡片 `text-align: center` 继承影响，
  结果整张图往右挪半个身位再被父级 `overflow: hidden` 切掉一半。`.state-mascot` 上那句
  `text-align: left` 就是治这个的，不是笔误；微信端原生 `image` 没这个坑。

三张共 ~107 KB，走 `import` 交给 webpack（weapp 端编译成 `/assets/hero/*.png`，
H5 端进 `static/images/`），主包 2M 上限下留足余量。

## 七、测试

```bash
npm test          # node --test，不引 jest/vitest
npm run typecheck
npm run build:weapp && npm run build:h5
```

- `tests/format.test.ts`：格式化与配色映射的纯函数单测（万/亿、增长率 `—`、
  新鲜度文案、真实/演示判定、趋势归一不产生 NaN）。
- `tests/favorites.test.ts`：收藏读写逻辑（脏数据丢弃、取消后删键、新收藏排最前）。
  纯逻辑与 Taro 存储适配层分在 `utils/favorites.ts` / `utils/store-taro.ts` 两个文件，
  否则顶层 `import @tarojs/taro` 会让 Node 跑不了单测。
- `tests/contract.test.ts`：对着**真实后端**逐字段核对小程序的类型假设——
  榜单与梗库的分母关系、卡片必填字段、详情介绍不许空白、趋势窗口只收 7/30、
  采信视频都过相关性阈值。后端没起时每条各自 skip 并说明原因，不会静默假通过。

## 八、这一端刻意没做什么

- 没有收藏/登录：V1 不做用户体系，Web 端的收藏是 localStorage，不跨端同步。
- 趋势图用 CSS 柱子而不是 ECharts/canvas：canvas 在 weapp 与 h5 两套实现差异大，
  柱子两边渲染一致，才能拿 H5 截图当 weapp 的视觉证据。
- 不接 AI 文案接口（`POST /api/memes/{id}/insight`）：详情页展示的是算法自己写的
  那句理由，AI 生成的那段只在 Web 端有，小程序不重复引一次 LLM 依赖。
